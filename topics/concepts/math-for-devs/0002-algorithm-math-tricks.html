Math Tricks for Algorithm Problem Solving

Prefix sums · XOR algebra · Ceiling division · Two's complement geometry · Pigeonhole · Difference arrays · Arithmetic progressions
The core idea The fastest algorithms don't compute harder — they compute differently. Each trick below transforms a naive approach (O(n) per query, O(n²) loop, branch-heavy logic) into something structurally faster by seeing the math from a different angle. Learn the pattern, not the individual problem.

1. Prefix Sums — precompute once, query in O(1)

The naive mistake: given an array, sum elements between index l and r every time you're asked. That's O(n) per query — if you answer Q queries, it's O(n × Q) total.

The insight: precompute a running total. Then any range sum is two array lookups and a subtraction.

PATTERN — Prefix Sum
prefix[0] = 0
prefix[i] = prefix[i-1] + arr[i-1] (1-indexed)

sum(l, r) = prefix[r+1] - prefix[l] → O(1) per query after O(n) setup 
// Build prefix sum array — O(n) once
int[] prefix = new int[n + 1];
for (int i = 0; i < n; i++) {
    prefix[i + 1] = prefix[i] + arr[i];
}

// Range sum [l, r] inclusive — O(1)
int rangeSum = prefix[r + 1] - prefix[l];
ApproachPer queryTotal (Q queries)
Naive loop each timeO(n)O(n × Q)
Prefix sumO(1)O(n + Q)
Where it appears Range sum queries (LeetCode #303, #304 2D variant), subarray sum equals K (#560), product arrays (#238), sliding window problems where the window condition involves a running total.
2D prefix sums The same trick extends to matrices: prefix[i][j] = sum of the rectangle from (0,0) to (i-1,j-1). Any sub-rectangle query becomes: P[r2+1][c2+1] - P[r1][c2+1] - P[r2+1][c1] + P[r1][c1] — four lookups, O(1).

2. XOR Algebra — cancellation as a tool

XOR has three properties that make it a surprisingly sharp instrument:

a ^ a = 0
a ^ 0 = a
a ^ b = b ^ a
(a^b)^c = a^(b^c)

Translation: XOR-ing the same number twice cancels it out. Every value is its own inverse. Order doesn't matter.

Find the missing number in 0..n

Given an array with all numbers 1..n except one, find the missing number without sorting or a hash set.

// XOR all indices 0..n, then XOR all values.
// Paired values cancel; unpaired index (the missing number) survives.
int missing = n;
for (int i = 0; i < n; i++) {
    missing ^= i ^ arr[i];
}

Space: O(1). Time: O(n). The same pattern finds two non-repeating elements in an array of duplicates.

Swap two integers without a temp variable

a ^= b;   // a = a ^ b
b ^= a;   // b = b ^ (a ^ b) = a
a ^= b;   // a = (a ^ b) ^ a = b
Caution This breaks if a and b are the same memory location (same pointer). Always use a temp variable in production Java — this trick exists so you can recognise it in interviews, not to write it in services.

Detect if two integers have opposite signs

boolean oppositeSign = (a ^ b) < 0;  // sign bit differs → XOR sign bit = 1 → negative
Where it appears LeetCode #136 (single number), #137 (single number II), #260 (two unique numbers), #268 (missing number), #389 (find difference). Recognise "find the odd-one-out" → reach for XOR.

3. Ceiling Division & Rounding Tricks

Integer division in Java truncates toward zero. When you need the ceiling (round up), a common mistake is converting to float.

PATTERN — Integer Ceiling Division
ceil(a / b) = (a + b - 1) / b   →   integer arithmetic, no float, no branch

Why it works: adding b - 1 to a pushes any remainder over the threshold that forces a higher quotient, then truncation brings it back down exactly to the ceiling.

// How many pages of size PAGE_SIZE fit n items?
int pages = (n + PAGE_SIZE - 1) / PAGE_SIZE;

// How many chunks of 8 bits to hold n bits?
int bytes = (n + 7) / 8;

// How many full weeks to complete n days?
int weeks = (n + 6) / 7;

Aligning to a power-of-2 boundary

// Round x UP to nearest multiple of align (must be power of 2)
int aligned = (x + align - 1) & ~(align - 1);

// Round x DOWN to nearest multiple of align
int aligned = x & ~(align - 1);

This appears in memory allocators, cache-line alignment, and disk block addressing. The ~(align-1) mask clears the low bits that would represent the remainder.

Related: is x a multiple of n? x % n == 0 when n is a power of 2 can be written as (x & (n-1)) == 0 — same bitwise-AND-as-modulo trick from lesson 1.

4. Two's Complement Geometry — low-bit tricks

Two's complement negation inverts all bits then adds 1. That +1 carries through the low zeros and flips the lowest set bit — everything below it becomes zero, everything above it is inverted. This geometry produces three extremely fast primitives:

OperationCodeWhat it does
Is power of two?(n > 0) && (n & (n-1)) == 0Clears lowest set bit; if result is 0, only one bit was set
Isolate lowest set bitn & (-n)Returns a value with only the rightmost 1-bit set
Clear lowest set bitn & (n-1)Turns off the rightmost 1-bit
Count set bits (Kernighan)while(n!=0){count++;n&=n-1;}Each iteration strips one set bit — O(set bits), not O(32)
Absolute value (no branch)int s=n>>31; (n^s)-sArithmetic right-shift fills with sign bit; XOR + subtract negates if negative
EXAMPLE — Count Set Bits (Kernighan's algorithm)
// Naive: 32 iterations always
// Kernighan: only as many iterations as there are 1-bits
int count = 0;
while (n != 0) {
    count++;
    n &= (n - 1);  // strip lowest set bit
}
If n = 1000 (decimal), it has 6 set bits in binary → only 6 iterations, not 32.

Fenwick Tree (Binary Indexed Tree) relies on these

A Fenwick Tree stores prefix sums with O(log n) update and query using exactly i += (i & -i) to move to parent nodes and i -= (i & -i) to move to next range — isolation of the lowest set bit is the entire navigation mechanism.

5. The Pigeonhole Principle — guarantee-based reasoning

If you put n+1 objects into n boxes, at least one box holds two or more objects.

This sounds trivial. In algorithm problem solving it unlocks proof-by-contradiction reasoning and guarantees the existence of a structure you can then search for efficiently.

Example: Find Duplicate in Array of n+1 Integers (1..n)

By pigeonhole, at least one value must appear twice. That doesn't tell you how to find it — but it guarantees a solution exists. Floyd's cycle detection (fast/slow pointers) exploits this: treat the array as a function f(i) = arr[i] and follow it like a linked list. A duplicate entry creates a cycle, and the cycle's entry point is the duplicate.

// Floyd's Cycle Detection — find duplicate without extra space
int slow = nums[0], fast = nums[0];
do {
    slow = nums[slow];
    fast = nums[nums[fast]];
} while (slow != fast);

// Find entry point of cycle = duplicate
fast = nums[0];
while (slow != fast) {
    slow = nums[slow];
    fast = nums[fast];
}
return slow;  // = duplicate value

Birthday Problem — probability meets pigeonhole

If you hash n items into m buckets, you expect a collision after roughly √m insertions, not m. At m = 365 days, collisions appear after ~23 people — not 183. This is why:

  • UUID collisions appear far sooner than the 2¹²⁸ space suggests (after ~2⁶⁴ IDs)
  • Hash tables need collision handling well before they're 100% full
  • Cryptographic birthday attacks (SHA-1 broken at ~2⁸⁰, not 2¹⁶⁰)
Where it appears LeetCode #287 (find duplicate), #442 (find duplicates in array), any "prove at least one X must exist" argument. Any capacity planning where you reason about expected collision rate.

6. Difference Arrays — O(1) range update

Prefix sums let you query a range sum in O(1) after O(n) setup. The difference array is the inverse trick: update a range in O(1), then reconstruct the full array in O(n).

PATTERN — Difference Array
To add val to every element in range [l, r]:

diff[l] += val
diff[r+1] -= val

Reconstruct by prefix-summing diff: arr[i] = arr[i-1] + diff[i] 
// Apply K range updates, then reconstruct — O(K + n) total
int[] diff = new int[n + 1];

// Each update: O(1)
for (int[] op : operations) {
    int l = op[0], r = op[1], val = op[2];
    diff[l] += val;
    if (r + 1 <= n) diff[r + 1] -= val;
}

// Reconstruct: O(n)
int[] result = new int[n];
int running = 0;
for (int i = 0; i < n; i++) {
    running += diff[i];
    result[i] = running;
}
OperationNaive arrayDifference array
Update range [l, r]O(n)O(1)
Reconstruct full arrayO(1)O(n) once at end
K updates + read allO(K × n)O(K + n)
Where it appears LeetCode #1109 (flight booking), #1854 (maximum population year), #370 (range addition), any "apply many range increments then read final values" problem.

7. Arithmetic Progression Identity

Sum of integers from 1 to n: n × (n+1) / 2. You almost certainly know this. What's less obvious is when to reach for it in algorithm problems.

PATTERN — Expected sum as a detection tool
If you have n distinct integers drawn from 1..n, their sum must equal n(n+1)/2. Any deviation reveals missing or extra elements without sorting or hashing. 
// Find missing number in [0..n] — O(n) time, O(1) space
int expected = n * (n + 1) / 2;
int actual   = Arrays.stream(nums).sum();
return expected - actual;

// Find missing and extra: difference = missing - extra
// Combined with XOR: one pass gives both

Gauss sum generalisation

  • Sum of a to b: (b - a + 1) × (a + b) / 2
  • Sum of even numbers 2..n: (n/2) × (n/2 + 1)
  • Sum of squares 1..n: n(n+1)(2n+1)/6 — appears in variance calculations and DP proofs
Overflow guard For large n, n * (n+1) overflows a 32-bit int before the division. Cast to long: (long)n * (n+1) / 2. This is a common off-by-one source in contest problems.

Practice Quiz

Q1 — You have an array of size n+1 with values in [1..n]. No sorting, no hash set, O(1) space. Which approach finds the duplicate?

  • Prefix sum after converting to diff array
  • Floyd's cycle detection via f(i) = arr[i]
  • XOR all indices then XOR all values
  • Gauss sum identity on the expected total
Pigeonhole guarantees a duplicate exists. Floyd's treats the array as a function to follow — the duplicate creates a cycle, and the entry point is the duplicate. XOR would also work for missing number, but not when there are duplicates (it cancels pairs, not extras).

Q2 — You must add +3 to every element in range [2, 7] of a 10-element array, 10,000 times with different ranges. Which data structure makes all updates O(1)?

  • Fenwick Tree (Binary Indexed Tree)
  • Segment Tree with lazy propagation
  • Difference array with prefix reconstruction
  • Prefix sum array rebuilt after each update
Difference array: mark diff[l]+=val, diff[r+1]-=val — O(1) per update. Reconstruct once with a prefix pass at the end. Segment tree/Fenwick handle point queries between updates; prefix sum rebuilding is O(n) per update — exactly what we're avoiding.

Q3 — What does n & (n-1) return when n is a power of 2?

  • Returns exactly zero and no other value
  • Returns the next lower power of two
  • Returns n with the high bit cleared
  • Returns n with all low bits set to one
n & (n-1) clears the lowest set bit. For a power of 2, the only set bit IS the lowest (and only) bit. Clearing it leaves zero. This is the O(1) power-of-2 check: (n > 0) && (n & (n-1)) == 0.

Q4 — You need ceiling division: how many groups of 7 fit at least n=50 items? Which expression is correct integer arithmetic?

  • (int) Math.ceil((double) 50 / 7)
  • 50 / 7 + (50 % 7 != 0 ? 1 : 0)
  • 50 / 7 + 1 regardless of remainder
  • (50 + 7 - 1) / 7 via integer arithmetic
(50 + 6) / 7 = 56 / 7 = 8. Option 1 works but involves float. Option 2 works but has a branch. Option 3 over-counts when 50 is exactly divisible. Option 4 is the canonical branchless integer ceiling formula.

Q5 — XOR all numbers 1..5, then XOR the array [1,2,4,5]. What does the result represent?

  • Sum of all paired elements combined
  • Missing number since paired values cancel
  • Duplicate element found via cancellation
  • XOR of remaining elements after pairing
1^2^3^4^5 ^ 1^2^4^5 = 3 — each value that appears twice cancels to 0, leaving only the unpaired value (3, the missing number). This is the O(n) time O(1) space missing-number algorithm.
