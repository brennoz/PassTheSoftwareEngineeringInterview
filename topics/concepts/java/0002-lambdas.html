Java Lambdas & Functional Interfaces

Category: Java · Topic: Lambdas & Functional Interfaces · Est. time: 25 min · Lesson 2 of 3

Lambdas, introduced in Java 8, let you pass behaviour as a value. Instead of creating a class to implement a single-method interface, you write an inline function. This changes how Java code is structured: conditions become reusable Predicate objects, transformations become composable Functions, and anonymous inner classes nearly disappear. The result is code that expresses what to do rather than how to iterate.

1. Before Lambdas — Anonymous Inner Classes

Before Java 8, passing behaviour required an anonymous inner class for every functional interface. Three patterns drove the most boilerplate.

Sorting a list of transactions

⛔ Java 7 — anonymous inner class
List<Transaction> txns = getTransactions();

// 5 lines just to express one comparison
Collections.sort(txns,
    new Comparator<Transaction>() {
        @Override
        public int compare(
                Transaction a, Transaction b) {
            return a.getAmount()
                    .compareTo(b.getAmount());
        }
    });
✅ Java 8 — lambda + method reference
List<Transaction> txns = getTransactions();

// Lambda — type inferred, one line
txns.sort((a, b) ->
    a.getAmount().compareTo(b.getAmount()));

// Method reference — even cleaner
txns.sort(
    Comparator.comparing(Transaction::getAmount));

Running a task on another thread

⛔ Java 7
executor.submit(new Runnable() {
    @Override
    public void run() {
        auditLog.record(event);
    }
});
✅ Java 8
executor.submit(
    () -> auditLog.record(event));

Filtering a collection

⛔ Java 7 — mutable accumulator
List<Bet> highStakeBets = new ArrayList<>();
for (Bet bet : allBets) {
    if (bet.getStake().compareTo(
            BigDecimal.valueOf(1000)) > 0) {
        highStakeBets.add(bet);
    }
}
// Logic mixed with iteration,
// result list is mutable
✅ Java 8 — stream + lambda
List<Bet> highStakeBets = allBets.stream()
    .filter(bet -> bet.getStake()
        .compareTo(BigDecimal.valueOf(1000)) > 0)
    .toList();
// Logic expressed as a predicate,
// result is unmodifiable
Why the verbosity matters Anonymous inner classes hide intent under structure. A 6-line Comparator forces the reader to parse syntax before understanding meaning. A lambda expresses the same contract in one line. Less code = smaller surface area for bugs, easier to name, easier to test.

2. Lambda Syntax

A lambda is an anonymous function: (parameters) -> body. Java infers parameter types from the target functional interface — you rarely need to write them.

// No parameters
Runnable r = () -> System.out.println("settling bets");

// One parameter — parentheses optional when type is inferred
Predicate<String> isIban = iban -> iban.startsWith("GB");
// Explicit type also valid:
Predicate<String> isIban = (String iban) -> iban.startsWith("GB");

// Two parameters — parentheses required
Comparator<Account> byBalance =
    (a, b) -> a.getBalance().compareTo(b.getBalance());

// Block body — multiple statements, explicit return required
Function<Transaction, String> summarise = tx -> {
    String direction = tx.getAmount().signum() > 0 ? "CREDIT" : "DEBIT";
    return direction + " " + tx.getAmount().abs() + " " + tx.getCurrency();
};

// Single void expression — no return needed
Consumer<Bet> log = bet -> System.out.println("Placed: " + bet.getId());

// Return type is ALWAYS inferred — never written in a lambda
@FunctionalInterface — the contract A functional interface has exactly ONE abstract method. The lambda provides the implementation of that method. Mark your own with @FunctionalInterface — the compiler enforces the single-abstract-method rule and generates a helpful error if you accidentally add a second abstract method. Default and static methods don't count. 
// Define your own functional interface
@FunctionalInterface
public interface RiskCheck {
    RiskDecision evaluate(Bet bet);  // single abstract method

    // default methods are fine — they don't count as abstract
    default RiskCheck and(RiskCheck other) {
        return bet -> {
            RiskDecision first = this.evaluate(bet);
            return first == RiskDecision.APPROVE
                ? other.evaluate(bet)
                : first;
        };
    }
}

// Use as a lambda
RiskCheck maxStakeCheck = bet ->
    bet.getStake().compareTo(MAX_STAKE) > 0
        ? RiskDecision.DECLINE
        : RiskDecision.APPROVE;

// Compose using the default method
RiskCheck combined = maxStakeCheck
    .and(velocityCheck)
    .and(selfExclusionCheck);
RiskDecision decision = combined.evaluate(incomingBet);

3. Built-in Functional Interfaces

Java 8 ships a complete set in java.util.function. These are used throughout the Streams API — knowing them by signature is essential for reading and writing Java 8+ code fluently.

InterfaceSignatureAbstract methodUse for
Predicate<T>T → booleantest(T t)Filtering, validation, conditions
Function<T,R>T → Rapply(T t)Transformation, type mapping
Consumer<T>T → voidaccept(T t)Side effects: logging, persisting
Supplier<T>() → Tget()Lazy evaluation, factory
BiFunction<T,U,R>T, U → Rapply(T t, U u)Two-input transformation
UnaryOperator<T>T → Tapply(T t)Transform where in/out type are same
BinaryOperator<T>T, T → Tapply(T t1, T t2)Combine two same-type values

Predicate<T> — test a condition, return boolean

⛔ Imperative — condition copy-pasted
// Same if-check in multiple callers
if (account.getBalance()
        .compareTo(BigDecimal.ZERO) < 0) {
    flagForReview(account);
}
// ... in another method ...
if (account.getBalance()
        .compareTo(BigDecimal.ZERO) < 0) {
    sendAlert(account);
}
// Change the rule? Find every copy.
✅ Predicate — defined once, reused everywhere
Predicate<Account> isOverdrawn =
    acct -> acct.getBalance()
        .compareTo(BigDecimal.ZERO) < 0;

// One definition, multiple use sites
accounts.stream()
    .filter(isOverdrawn)
    .forEach(this::flagForReview);

accounts.stream()
    .filter(isOverdrawn)
    .forEach(alertService::sendAlert);
// Change the rule? Update one line.

Function<T,R> — transform one type into another

⛔ Imperative
// PCI-DSS: mask PAN to last 4 digits
List<String> masked = new ArrayList<>();
for (Card card : cards) {
    String pan = card.getPan();
    masked.add(
        "****-****-****-"
        + pan.substring(pan.length() - 4));
}
✅ Function + stream
Function<Card, String> maskPan = card -> {
    String pan = card.getPan();
    return "****-****-****-"
        + pan.substring(pan.length() - 4);
};

List<String> masked = cards.stream()
    .map(maskPan)
    .toList();
// maskPan is independently testable

Consumer<T> — act on a value, return nothing

// Consumer encapsulates a side effect
Consumer<SettledBet> persist  = bet -> betRepo.save(bet);
Consumer<SettledBet> publish  = bet -> eventBus.publish(bet);
Consumer<SettledBet> sendReceipt = bet ->
    emailService.sendSettlementReceipt(bet.getCustomerEmail(), bet);

// andThen — chain two Consumers, run sequentially
Consumer<SettledBet> fullFlow =
    persist.andThen(publish).andThen(sendReceipt);

settledBets.forEach(fullFlow);
// Every settled bet is persisted, published, and emailed —
// in that order, in one named operation

Supplier<T> — produce a value lazily, on demand

// Supplier delays evaluation — critical for expensive defaults

// BAD: createDefaultAccount() is called even if the account is found
Account account = accountRepo.findById(id)
    .orElse(createDefaultAccount());   // always executed

// GOOD: Supplier — only called if Optional is empty
Account account = accountRepo.findById(id)
    .orElseGet(() -> createDefaultAccount()); // lazy

// Supplier as factory — defer object construction
Supplier<BetSlip> freshSlip = BetSlip::new;  // constructor ref
BetSlip slip = freshSlip.get();              // creates only when needed

// Supplier in retry / fallback pattern
Supplier<PriceDto> priceLoader =
    () -> priceService.getLatestPrice(marketId);
PriceDto price = retryTemplate.execute(priceLoader);

BiFunction<T,U,R> — two inputs, one output

// Currency conversion: amount + rate → converted amount
BiFunction<BigDecimal, ExchangeRate, BigDecimal> convert =
    (amount, rate) -> amount.multiply(rate.getRate())
                            .setScale(2, RoundingMode.HALF_UP);

BigDecimal gbp = convert.apply(usdAmount, usdToGbpRate);

// andThen — pipe result into a Function
BiFunction<Bet, Odds, String> describePayout =
    ((BiFunction<Bet, Odds, BigDecimal>)
        (bet, odds) -> bet.getStake().multiply(odds.getDecimal()))
    .andThen(payout -> "£" + payout.toPlainString());

String display = describePayout.apply(bet, odds);

UnaryOperator and BinaryOperator

// UnaryOperator<T> — T → T (same type in and out)
// Used where Function<T,T> would be, more expressive signature
UnaryOperator<BigDecimal> applyVat =
    amount -> amount.multiply(BigDecimal.valueOf(1.20))
                    .setScale(2, RoundingMode.HALF_UP);

// BinaryOperator<T> — (T, T) → T
// Combining two values of the same type
BinaryOperator<BigDecimal> sumAmounts = BigDecimal::add;
BigDecimal total = transactions.stream()
    .map(Transaction::getAmount)
    .reduce(BigDecimal.ZERO, sumAmounts);

// BinaryOperator in stream reduce:
BinaryOperator<BigDecimal> keepHigher = BigDecimal::max;
BigDecimal maxStake = bets.stream()
    .map(Bet::getStake)
    .reduce(BigDecimal.ZERO, keepHigher);

4. Method References — Four Types

Method references are shorthand for lambdas that do nothing except call a single named method. Use them when the lambda body is exactly one method call — they remove parameter noise and read like intent.

TypeSyntaxEquivalent lambda
Static methodClassName::staticMethodx -> ClassName.staticMethod(x)
Bound instanceinstance::methodx -> instance.method(x)
Unbound instanceClassName::instanceMethodx -> x.instanceMethod()
ConstructorClassName::newargs -> new ClassName(args)
 
// 1. STATIC method reference
// Lambda equivalent: tx -> TransactionValidator.isValid(tx)
transactions.stream()
    .filter(TransactionValidator::isValid)   // static method on the class
    .toList();

// Lambda equivalent: s -> String.valueOf(s)
List<String> asStrings = codes.stream()
    .map(String::valueOf)
    .toList();

// 2. BOUND instance method reference
// A specific object instance is captured — method called on THAT object
AuditLogger logger = new AuditLogger("bet-service");
// Lambda equivalent: bet -> logger.log(bet)
settledBets.forEach(logger::log);           // logger is the bound instance

// 3. UNBOUND instance method reference
// No captured instance — method is called on each STREAM ELEMENT
// Lambda equivalent: account -> account.getBalance()
List<BigDecimal> balances = accounts.stream()
    .map(Account::getBalance)               // getBalance() on each Account
    .toList();

// Lambda equivalent: s -> s.toUpperCase()
List<String> upper = currencies.stream()
    .map(String::toUpperCase)
    .toList();

// Two-param unbound: (a, b) -> a.compareTo(b)
transactions.sort(
    Comparator.comparing(Transaction::getAmount)
              .thenComparing(Transaction::getTimestamp));

// 4. CONSTRUCTOR reference
// Lambda equivalent: dto -> new Account(dto)
List<Account> accounts = dtos.stream()
    .map(Account::new)                      // calls Account(AccountDto)
    .toList();
When NOT to use method references If the lambda chains two calls (t -> t.getAmount().abs()), transforms parameters, or adds a conditional — there is no method reference for that. Forcing one adds a helper method just to make syntax shorter. Keep method references for true delegation: "call exactly this named operation on each element."

5. Function Composition

Functional interfaces compose — you assemble larger pipelines from small, named pieces without nesting calls. This is the functional equivalent of the Strategy pattern: behaviour is a first-class value you can pass, combine, and test independently.

// Function.andThen — apply f first, then pass result to g
// f.andThen(g) = x -> g(f(x))
Function<String, String> trim  = String::trim;
Function<String, String> upper = String::toUpperCase;
Function<String, String> clean = trim.andThen(upper);
clean.apply("  gb29 nwbk ...  "); // → "GB29 NWBK ..."

// Function.compose — apply g FIRST, then f (reverse of andThen)
// f.compose(g) = x -> f(g(x))
Function<String, String> cleanAlt = upper.compose(trim); // same result

// Chain multiple transformations
Function<String, BigDecimal> parseAmount =
    ((Function<String, String>) String::trim)
        .andThen(String::toUpperCase)
        .andThen(s -> s.replace(",", ""))
        .andThen(BigDecimal::new);

parseAmount.apply("  1,234.56  "); // → BigDecimal("1234.56")
// Predicate.and() / or() / negate() — compose boolean conditions
Predicate<Bet> isHighStake =
    bet -> bet.getStake().compareTo(BigDecimal.valueOf(500)) > 0;
Predicate<Bet> isInPlay    = Bet::isInPlay;
Predicate<Bet> isSuspect   = Bet::isFlaggedForReview;

// Compose — readable, no nested ifs
Predicate<Bet> requiresManualReview =
    isHighStake.and(isInPlay).or(isSuspect);

List<Bet> flagged = bets.stream()
    .filter(requiresManualReview)
    .toList();

// Negate
List<Bet> normal = bets.stream()
    .filter(requiresManualReview.negate())
    .toList();
⛔ Imperative — nested ifs, no reuse
List<Bet> flagged = new ArrayList<>();
for (Bet bet : bets) {
    boolean high  = bet.getStake()
        .compareTo(BigDecimal.valueOf(500)) > 0;
    boolean live  = bet.isInPlay();
    boolean alert = bet.isFlaggedForReview();
    if ((high && live) || alert) {
        flagged.add(bet);
    }
}
// Add 4th rule = edit this loop, re-test all
✅ Composed predicates — extend by adding one line
Predicate<Bet> requiresManualReview =
    isHighStake
        .and(isInPlay)
        .or(isSuspect);
        // .or(newRule) — one addition, nothing else changes

List<Bet> flagged = bets.stream()
    .filter(requiresManualReview)
    .toList();
// Each predicate is named, testable in isolation
This is the Open/Closed Principle (OCP) in practice OCP from SOLID: open for extension, closed for modification. Composed predicates achieve this without inheritance — add a new rule by composing, not by editing existing conditions.

6. Closures & Effectively Final

A lambda can reference variables from the enclosing scope — it "closes over" them. Java requires those variables to be effectively final: assigned once, never reassigned after initialisation.

// GOOD — threshold assigned once, never reassigned → effectively final
BigDecimal threshold = config.getHighValueThreshold();
Predicate<Transaction> isHighValue =
    tx -> tx.getAmount().compareTo(threshold) > 0; // OK

// BAD — compile error
BigDecimal threshold = BigDecimal.valueOf(1000);
threshold = config.getOverride();             // ← reassignment
Predicate<Transaction> isHighValue =
    tx -> tx.getAmount().compareTo(threshold) > 0;
// ERROR: local variable threshold defined in an enclosing scope
//        must be final or effectively final
Why effectively final? Lambdas may execute on a different thread or at a later time than their declaration site. If a captured local variable could change between declaration and execution, the lambda would observe inconsistent state — a data race with no synchronisation. Effectively final gives the compiler a guarantee: the value the lambda sees is always the value at capture time. 
// Workaround 1 — assign to a new final-looking variable
BigDecimal base     = BigDecimal.valueOf(1000);
BigDecimal override = config.getOverride();
BigDecimal threshold = override != null ? override : base; // final from here
Predicate<Transaction> isHighValue =
    tx -> tx.getAmount().compareTo(threshold) > 0; // OK

// Workaround 2 — pass as a method parameter (cleanest)
// Method params are effectively final unless explicitly reassigned
private Predicate<Transaction> highValueFilter(BigDecimal threshold) {
    return tx -> tx.getAmount().compareTo(threshold) > 0;
}
// Caller injects the threshold; lambda captures the param — always final.

// Workaround 3 — AtomicReference (avoid in hot paths — adds indirection)
AtomicReference<BigDecimal> thresholdRef =
    new AtomicReference<>(config.getHighValueThreshold());
thresholdRef.set(config.getOverride()); // mutate via ref; ref itself is final
Predicate<Transaction> isHighValue =
    tx -> tx.getAmount().compareTo(thresholdRef.get()) > 0;
// thresholdRef variable never reassigned → effectively final

Quiz

Q1. Which built-in functional interface has the signature T → boolean?

  • Function<T,R> — transforms T to a different type R
  • Predicate<T> — tests a condition on T, returns boolean
  • Consumer<T> — accepts T and returns void
  • Supplier<T> — takes no input and returns T
Predicate<T> has abstract method boolean test(T t). It takes a T and returns a boolean — used for filtering and validation. Function<T,R> transforms to a different type R. Consumer<T> returns void. Supplier<T> takes no arguments.

Q2. What does f.andThen(g) do for two Functions f and g?

  • Applies f first, then passes f’s result as input to g — equivalent to x -> g(f(x))
  • Applies g first, then passes g’s result as input to f — equivalent to x -> f(g(x))
  • Applies f and g to the same input in parallel, then combines both results
  • Returns a new Function that skips f and only calls g on the input
f.andThen(g) is the pipeline x -> g(f(x)): f runs first, its output is passed to g. f.compose(g) is the reverse: x -> f(g(x)) — g first, then f. Use andThen when you want left-to-right reading order.

Q3. Which variables can a lambda capture from the enclosing scope?

  • Any local variable, including those that are reassigned later
  • Only instance fields of the enclosing class, never local variables
  • Only effectively final local variables — assigned once, never reassigned after initialisation
  • Only static fields declared at class level
Captured local variables must be effectively final: they may not be reassigned after the point of first assignment. This prevents data races when the lambda runs on a different thread. Instance fields (via this) and static fields are freely accessible because the lambda holds a reference, not a snapshot.

Q4. Account::getBalance used in .map(Account::getBalance) is which type of method reference?

  • Static method reference — calls a static method on the Account class
  • Unbound instance method reference — getBalance() is called on each Account element in the stream
  • Bound instance method reference — a specific Account instance is captured at declaration time
  • Constructor reference — creates new Account instances from some input
Account::getBalance is unbound: no specific Account instance is captured. When used in a stream, the runtime calls getBalance() on each element as it flows through. A bound reference would be myAccount::getBalance where myAccount is a specific captured variable.

Q5. What does p.negate().test(3) return if Predicate<Integer> p = x -> x > 5?

  • true — 3 is not > 5 so p.test(3) is false; negate() flips it to true
  • false — 3 is not > 5 so the result stays false
  • Compile error — negate() is not available on Predicate
  • Runtime exception — integer comparison throws for unboxed types
p.test(3) evaluates 3 > 5 = false. p.negate() returns a new Predicate that inverts the result, so p.negate().test(3) = !false = true. negate() is a default method on Predicate<T>, available since Java 8.
