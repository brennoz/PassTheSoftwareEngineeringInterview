1 · HashMap / HashSet

Core insight Trade O(n) space for O(1) lookup. Instead of nested loops (O(n²)), scan once and store seen values / frequencies / complements in a map.

// TWO SUM — canonical HashMap template (q001)
public int[] twoSum(int[] nums, int target) {
    Map<Integer, Integer> seen = new HashMap<>();  // value → index
    for (int i = 0; i < nums.length; i++) {
        int complement = target - nums[i];
        if (seen.containsKey(complement))
            return new int[]{seen.get(complement), i};
        seen.put(nums[i], i);
    }
    return new int[]{};
}

// FREQUENCY COUNT template
Map<Character, Integer> freq = new HashMap<>();
for (char c : s.toCharArray())
    freq.merge(c, 1, Integer::sum);   // Java 8+: add 1, or insert 1 if absent

// LONGEST CONSECUTIVE — HashSet + only scan from sequence start
Set<Integer> set = new HashSet<>(Arrays.asList(nums));
int best = 0;
for (int n : set) {
    if (!set.contains(n - 1)) {      // n is a sequence start
        int len = 0;
        while (set.contains(n++)) len++;
        best = Math.max(best, len);
    }
}

2 · Two Pointers

Core insight On a sorted array, two pointers converging from opposite ends let you adjust the sum by moving left (increase) or right (decrease) — O(n) instead of O(n²) brute force.
Animation — Two Pointers converging on sorted array
// TWO POINTERS template — sorted array, find pair summing to target
public int[] twoSum(int[] sorted, int target) {
    int left = 0, right = sorted.length - 1;
    while (left < right) {
        int sum = sorted[left] + sorted[right];
        if (sum == target)  return new int[]{left, right};
        else if (sum < target) left++;   // too small → move left pointer right
        else                   right--;  // too large → move right pointer left
    }
    return new int[]{};
}

// 3SUM (q029) — fix one, two-pointer on the rest
Arrays.sort(nums);
for (int i = 0; i < nums.length - 2; i++) {
    if (i > 0 && nums[i] == nums[i-1]) continue;  // skip duplicates
    int left = i + 1, right = nums.length - 1;
    while (left < right) {
        int sum = nums[i] + nums[left] + nums[right];
        if (sum == 0) { result.add(...); left++; right--; }
        else if (sum < 0) left++;
        else right--;
    }
}

// VALID PALINDROME (q123) — converge, skip non-alphanumeric
int l = 0, r = s.length() - 1;
while (l < r) {
    while (l < r && !Character.isLetterOrDigit(s.charAt(l))) l++;
    while (l < r && !Character.isLetterOrDigit(s.charAt(r))) r--;
    if (Character.toLowerCase(s.charAt(l)) != Character.toLowerCase(s.charAt(r))) return false;
    l++; r--;
}

3 · Sliding Window

Core insight A window [left, right] slides over the array. Expand right to grow; shrink from left when a constraint is violated. Frequency map or counter tracks what's inside the window.
Animation — Variable sliding window: longest substring without repeat
// VARIABLE WINDOW — longest substring without repeating chars (q004)
public int lengthOfLongestSubstring(String s) {
    Map<Character, Integer> window = new HashMap<>();
    int left = 0, best = 0;
    for (int right = 0; right < s.length(); right++) {
        char c = s.charAt(right);
        window.merge(c, 1, Integer::sum);          // add to window
        while (window.get(c) > 1) {                // constraint violated
            char lc = s.charAt(left++);
            window.merge(lc, -1, Integer::sum);    // shrink from left
            if (window.get(lc) == 0) window.remove(lc);
        }
        best = Math.max(best, right - left + 1);
    }
    return best;
}

// MINIMUM WINDOW SUBSTRING (q109) — need/have counter pattern
// 1. Build 'need' map from t.  2. Expand right; when char in need, have++.
// 3. When have == need.size(), try to shrink left.  4. Track min window.
int have = 0, need = needMap.size();
while (have == need) {
    // update result with window [left, right]
    char lc = s.charAt(left++);
    if (needMap.containsKey(lc)) {
        windowMap.merge(lc, -1, Integer::sum);
        if (windowMap.get(lc) < needMap.get(lc)) have--;
    }
}

// BEST TIME TO BUY AND SELL (q009) — single pass, track min so far
int minPrice = Integer.MAX_VALUE, maxProfit = 0;
for (int price : prices) {
    minPrice = Math.min(minPrice, price);
    maxProfit = Math.max(maxProfit, price - minPrice);
}

4 · Binary Search

Core insight Every iteration halves the search space. Works on any monotonic condition — not just sorted arrays. If you can ask "is the answer ≤ x?" in O(n), you can binary search on the answer space. 
// STANDARD binary search template — avoids overflow
int left = 0, right = nums.length - 1;
while (left <= right) {
    int mid = left + (right - left) / 2;   // NOT (left+right)/2 — overflow risk
    if (nums[mid] == target) return mid;
    else if (nums[mid] < target) left = mid + 1;
    else right = mid - 1;
}
return -1;

// ROTATED SORTED ARRAY — find minimum (q092)
// Key: one half is always sorted; check which half and narrow search
int left = 0, right = nums.length - 1;
while (left < right) {
    int mid = left + (right - left) / 2;
    if (nums[mid] > nums[right]) left = mid + 1;  // min is in right half
    else right = mid;                              // min is in left half (or mid)
}
return nums[left];

// SEARCH IN ROTATED SORTED ARRAY (q093)
// At every mid, one half is sorted. Use that to decide which half to search.
while (left <= right) {
    int mid = left + (right - left) / 2;
    if (nums[mid] == target) return mid;
    if (nums[left] <= nums[mid]) {                 // left half sorted
        if (nums[left] <= target && target < nums[mid]) right = mid - 1;
        else left = mid + 1;
    } else {                                       // right half sorted
        if (nums[mid] < target && target <= nums[right]) left = mid + 1;
        else right = mid - 1;
    }
}
Binary search on answer space Classic pattern: "find minimum X such that condition(X) is true." Set left=minPossible, right=maxPossible, binary search. At each mid, check condition(mid) in O(n). Total: O(n log n). Example: "minimum speed to eat bananas in H hours."

5 · Stack

Core insight Stack = last-in-first-out. Push when opening; pop when closing. Peek to compare with current. Use for matching brackets, expression evaluation, "next greater element" (monotonic stack). 
// VALID PARENTHESES (q003)
Deque<Character> stack = new ArrayDeque<>();
Map<Character, Character> pairs = Map.of(')', '(', ']', '[', '}', '{');
for (char c : s.toCharArray()) {
    if (!pairs.containsKey(c)) { stack.push(c); continue; }  // open bracket
    if (stack.isEmpty() || stack.peek() != pairs.get(c)) return false;
    stack.pop();
}
return stack.isEmpty();

// MONOTONIC STACK — "next greater element to the right"
int[] result = new int[nums.length];
Deque<Integer> stack = new ArrayDeque<>();  // indices
for (int i = 0; i < nums.length; i++) {
    while (!stack.isEmpty() && nums[i] > nums[stack.peek()])
        result[stack.pop()] = nums[i];   // i is the "next greater" for popped index
    stack.push(i);
}
// remaining in stack: no next greater element → result[i] = -1 (default)

// STACK IMPLEMENTATION without array (q110) — use linked list node
class Stack {
    private record Node(int val, Node next) {}
    private Node top;
    public void push(int x) { top = new Node(x, top); }
    public int pop()  { int v = top.val(); top = top.next(); return v; }
    public int peek() { return top.val(); }
}

6 · Linked List Pointers

Core insight Two classic techniques: (1) prev/cur/next in-place mutation for reversal; (2) fast/slow (Floyd's) for cycle detection and nth-from-end. Both O(1) space. 
// REVERSE LINKED LIST (q101) — iterative prev/cur/next
ListNode prev = null, cur = head;
while (cur != null) {
    ListNode next = cur.next;  // save next
    cur.next = prev;           // reverse link
    prev = cur;                // advance prev
    cur = next;                // advance cur
}
return prev;  // new head

// CYCLE DETECTION — Floyd's fast/slow (q103)
ListNode slow = head, fast = head;
while (fast != null && fast.next != null) {
    slow = slow.next;
    fast = fast.next.next;
    if (slow == fast) return true;  // cycle
}
return false;

// NTH FROM END (q104) — advance fast by n first, then move both
ListNode fast = head, slow = head;
for (int i = 0; i < n; i++) fast = fast.next;
while (fast.next != null) { slow = slow.next; fast = fast.next; }
slow.next = slow.next.next;  // remove nth from end

// MERGE TWO SORTED LISTS (q102) — dummy head avoids edge cases
ListNode dummy = new ListNode(0), cur = dummy;
while (l1 != null && l2 != null) {
    if (l1.val <= l2.val) { cur.next = l1; l1 = l1.next; }
    else                   { cur.next = l2; l2 = l2.next; }
    cur = cur.next;
}
cur.next = (l1 != null) ? l1 : l2;
return dummy.next;

7 · Tree DFS (recursion)

Core insight Recursive DFS decomposes a tree problem into: base case (null) + left subtree result + right subtree result + combine. Most tree problems are 3–5 lines once you see the recurrence. 
// MAX DEPTH (q113)
public int maxDepth(TreeNode root) {
    if (root == null) return 0;
    return 1 + Math.max(maxDepth(root.left), maxDepth(root.right));
}

// INVERT BINARY TREE (q114)
public TreeNode invertTree(TreeNode root) {
    if (root == null) return null;
    TreeNode tmp = root.left;
    root.left = invertTree(root.right);
    root.right = invertTree(tmp);
    return root;
}

// VALIDATE BST (q120) — pass bounds down the recursion
public boolean isValidBST(TreeNode node, long min, long max) {
    if (node == null) return true;
    if (node.val <= min || node.val >= max) return false;
    return isValidBST(node.left, min, node.val)
        && isValidBST(node.right, node.val, max);
}
// call: isValidBST(root, Long.MIN_VALUE, Long.MAX_VALUE)

// LOWEST COMMON ANCESTOR BST (q121)
public TreeNode lca(TreeNode root, TreeNode p, TreeNode q) {
    if (p.val < root.val && q.val < root.val) return lca(root.left, p, q);
    if (p.val > root.val && q.val > root.val) return lca(root.right, p, q);
    return root;  // split point = LCA
}

// Pre-order:  process node, then left, then right
// In-order:   left, node, right  → sorted output for BST
// Post-order: left, right, node  → used for deletion, expression eval

8 · Tree BFS (queue)

Core insight BFS uses a queue. Process all nodes at level N before moving to level N+1. At the start of each level, the queue size = number of nodes at that level — snapshot it before the inner loop. 
// LEVEL ORDER TRAVERSAL (q119) — canonical BFS template
public List<List<Integer>> levelOrder(TreeNode root) {
    List<List<Integer>> result = new ArrayList<>();
    if (root == null) return result;
    Queue<TreeNode> queue = new LinkedList<>();
    queue.offer(root);
    while (!queue.isEmpty()) {
        int levelSize = queue.size();    // snapshot BEFORE inner loop
        List<Integer> level = new ArrayList<>();
        for (int i = 0; i < levelSize; i++) {
            TreeNode node = queue.poll();
            level.add(node.val);
            if (node.left  != null) queue.offer(node.left);
            if (node.right != null) queue.offer(node.right);
        }
        result.add(level);
    }
    return result;
}
BFS vs DFS on trees
Use BFS when the answer involves level (depth, width, level-order output). Use DFS when the answer can be computed at a single node using only its subtree results (max depth, path sum, validate BST). DFS space = O(h); BFS space = O(w) = O(n) at worst for a complete binary tree.

9 · Graph BFS / DFS / Dijkstra

Core insight Always track visited nodes to avoid infinite loops. BFS gives shortest path in unweighted graphs (level = distance). DFS is simpler for connectivity/cycle. Dijkstra handles weighted edges via a min-heap.
Animation — BFS (level-by-level) | DFS (depth-first) | Dijkstra (weighted shortest path)
// BFS — shortest path unweighted (q097)
public Map<Integer, Integer> bfs(Map<Integer, List<Integer>> adj, int start) {
    Map<Integer, Integer> dist = new HashMap<>();
    Queue<Integer> queue = new LinkedList<>();
    queue.offer(start); dist.put(start, 0);
    while (!queue.isEmpty()) {
        int node = queue.poll();
        for (int nb : adj.getOrDefault(node, List.of())) {
            if (!dist.containsKey(nb)) {
                dist.put(nb, dist.get(node) + 1);
                queue.offer(nb);
            }
        }
    }
    return dist;
}

// DFS — number of islands (q022)  [grid BFS/DFS same idea]
private void dfs(char[][] grid, int r, int c) {
    if (r < 0 || r >= grid.length || c < 0 || c >= grid[0].length || grid[r][c] != '1') return;
    grid[r][c] = '0';  // mark visited in-place
    dfs(grid, r+1, c); dfs(grid, r-1, c);
    dfs(grid, r, c+1); dfs(grid, r, c-1);
}
int count = 0;
for (int r = 0; r < grid.length; r++)
    for (int c = 0; c < grid[0].length; c++)
        if (grid[r][c] == '1') { dfs(grid, r, c); count++; }

// DIJKSTRA — weighted shortest path (q099)
PriorityQueue<int[]> pq = new PriorityQueue<>(Comparator.comparingInt(a -> a[1]));
pq.offer(new int[]{start, 0});
Map<Integer, Integer> dist = new HashMap<>();
while (!pq.isEmpty()) {
    int[] curr = pq.poll();
    int node = curr[0], d = curr[1];
    if (dist.containsKey(node)) continue;   // already settled
    dist.put(node, d);
    for (int[] edge : adj.getOrDefault(node, List.of())) {
        int nb = edge[0], w = edge[1];
        if (!dist.containsKey(nb)) pq.offer(new int[]{nb, d + w});
    }
}

10 · Dynamic Programming

Core insight DP = recursion + memoisation. Top-down: write the recursion, add a cache. Bottom-up: fill a table from smallest subproblem to largest. Identify: (1) state definition, (2) recurrence, (3) base case.

Top-down (memoisation)

  • Write the natural recursion first
  • Add Map<State, Result> memo
  • Return cached value if present
  • Easier to reason about; overhead of map + stack frames

Bottom-up (tabulation)

  • Fill dp[i] from dp[0] upwards
  • No recursion overhead; often space-optimisable
  • Requires identifying the right iteration order
  • Preferred in interviews (clearer, no stack overflow risk)
// MAXIMUM SUBARRAY — Kadane's algorithm (q011)
// dp[i] = max subarray ending at i = max(nums[i], dp[i-1] + nums[i])
int maxSum = nums[0], cur = nums[0];
for (int i = 1; i < nums.length; i++) {
    cur = Math.max(nums[i], cur + nums[i]);   // extend or restart
    maxSum = Math.max(maxSum, cur);
}

// FIBONACCI — bottom-up O(1) space (q106)
int a = 0, b = 1;
for (int i = 2; i <= n; i++) { int c = a + b; a = b; b = c; }
return b;

// FIBONACCI — top-down memoisation (q106 alt)
Map<Integer, Long> memo = new HashMap<>();
long fib(int n) {
    if (n <= 1) return n;
    if (memo.containsKey(n)) return memo.get(n);
    long res = fib(n-1) + fib(n-2);
    memo.put(n, res);
    return res;
}

// DP TEMPLATE — "climb stairs" / coin change pattern
int[] dp = new int[n + 1];
dp[0] = 1;  // base case: one way to reach 0
for (int i = 1; i <= n; i++)
    for (int coin : coins)
        if (i - coin >= 0)
            dp[i] += dp[i - coin];

11 · Greedy

Core insight Make the locally optimal choice at each step. Works when the problem has the greedy choice property — optimal substructure + no need to backtrack. Sort first, then greedily pick. 
// ACTIVITY SELECTION / INTERVAL SCHEDULING — greedily pick earliest end time
Arrays.sort(intervals, Comparator.comparingInt(a -> a[1]));  // sort by end time
int count = 0, lastEnd = Integer.MIN_VALUE;
for (int[] interval : intervals) {
    if (interval[0] >= lastEnd) {  // no overlap with last selected
        count++;
        lastEnd = interval[1];
    }
}

// JUMP GAME — greedily track max reachable index
int maxReach = 0;
for (int i = 0; i < nums.length; i++) {
    if (i > maxReach) return false;           // stuck — can't reach i
    maxReach = Math.max(maxReach, i + nums[i]);
}
return true;
DP vs Greedy If you can always pick the locally optimal choice without looking ahead and it provably leads to the global optimum — use Greedy (faster). If choices affect future options and you need to explore alternatives — use DP. Greedy is O(n log n) at worst; DP is usually O(n²) or O(n·k).

12 · Intervals

Core insight Sort by start time. Two intervals overlap when b.start <= a.end. Merge by extending the current end: end = max(end, b.end). A min-heap on end times handles "meeting rooms" style problems. 
// MERGE INTERVALS (q007)
Arrays.sort(intervals, Comparator.comparingInt(a -> a[0]));
List<int[]> merged = new ArrayList<>();
for (int[] cur : intervals) {
    if (merged.isEmpty() || cur[0] > merged.get(merged.size()-1)[1]) {
        merged.add(cur);                                   // no overlap
    } else {
        merged.get(merged.size()-1)[1] =
            Math.max(merged.get(merged.size()-1)[1], cur[1]);  // extend
    }
}

// MEETING ROOMS II — min rooms needed (PriorityQueue on end times)
Arrays.sort(intervals, Comparator.comparingInt(a -> a[0]));
PriorityQueue<Integer> ends = new PriorityQueue<>();
for (int[] iv : intervals) {
    if (!ends.isEmpty() && ends.peek() <= iv[0]) ends.poll();  // free a room
    ends.offer(iv[1]);
}
return ends.size();  // rooms in use = answer

13 · Backtracking

Core insight DFS on an implicit decision tree. At each step: choose an option, recurse, then undo the choice (backtrack). Prune early when a partial solution already violates constraints. 
// GENERAL BACKTRACKING TEMPLATE
void backtrack(State state, List<State> result) {
    if (isSolution(state)) { result.add(copy(state)); return; }
    for (Choice c : getChoices(state)) {
        if (isValid(state, c)) {
            apply(state, c);           // choose
            backtrack(state, result);  // explore
            undo(state, c);            // un-choose (backtrack)
        }
    }
}

// SUDOKU SOLVER (q091) — find empty cell, try 1–9, recurse
boolean solve(char[][] board) {
    for (int r = 0; r < 9; r++) for (int c = 0; c < 9; c++) {
        if (board[r][c] != '.') continue;
        for (char ch = '1'; ch <= '9'; ch++) {
            if (isValid(board, r, c, ch)) {
                board[r][c] = ch;
                if (solve(board)) return true;
                board[r][c] = '.';  // backtrack
            }
        }
        return false;  // no valid digit → trigger backtrack in caller
    }
    return true;  // all cells filled
}

// SUBSETS — generate all subsets (include/exclude pattern)
void subsets(int[] nums, int idx, List<Integer> current, List<List<Integer>> result) {
    result.add(new ArrayList<>(current));    // every state is a valid subset
    for (int i = idx; i < nums.length; i++) {
        current.add(nums[i]);
        subsets(nums, i + 1, current, result);
        current.remove(current.size() - 1);  // backtrack
    }
}

14 · Trie (Prefix Tree)

Core insight Each node represents a character; the path from root to node = a prefix. Insert and search are O(L) where L = word length. Beats HashMap for prefix queries — no need to check every key. 
// TRIE IMPLEMENTATION (q122)
class TrieNode {
    TrieNode[] children = new TrieNode[26];
    boolean isEnd;
}

class Trie {
    private final TrieNode root = new TrieNode();

    public void insert(String word) {
        TrieNode cur = root;
        for (char c : word.toCharArray()) {
            int i = c - 'a';
            if (cur.children[i] == null) cur.children[i] = new TrieNode();
            cur = cur.children[i];
        }
        cur.isEnd = true;
    }

    public boolean search(String word) {
        TrieNode cur = root;
        for (char c : word.toCharArray()) {
            int i = c - 'a';
            if (cur.children[i] == null) return false;
            cur = cur.children[i];
        }
        return cur.isEnd;
    }

    public boolean startsWith(String prefix) {
        TrieNode cur = root;
        for (char c : prefix.toCharArray()) {
            int i = c - 'a';
            if (cur.children[i] == null) return false;
            cur = cur.children[i];
        }
        return true;  // any node reached = prefix exists
    }
}

15 · Bit Manipulation

Core insight Bitwise ops are O(1) and very fast. Key tricks: n & (n-1) clears the lowest set bit; n & 1 checks if odd; x ^ x = 0 (XOR cancellation for finding the lone element). 
// COUNT SET BITS (q095) — Brian Kernighan
int count = 0;
while (n != 0) { n = n & (n - 1); count++; }  // clear lowest set bit each time

// COUNTING BITS for 0..n (q094) — DP: dp[i] = dp[i >> 1] + (i & 1)
int[] dp = new int[n + 1];
for (int i = 1; i <= n; i++)
    dp[i] = dp[i >> 1] + (i & 1);  // i>>1 = i/2; (i&1) = last bit

// REVERSE BITS (q096)
int result = 0;
for (int i = 0; i < 32; i++) {
    result = (result << 1) | (n & 1);  // shift result left, add LSB of n
    n >>>= 1;                           // unsigned right shift n
}

// COMMON BIT TRICKS
n & 1           // is odd?
n & (n-1)       // clear lowest set bit
n & (-n)        // isolate lowest set bit
(n & (n-1)) == 0  // is power of 2?
a ^ b           // XOR: find single non-duplicate in array (pairs cancel)
1 << k          // set bit k
n >>> k         // unsigned right shift (no sign extension)

Quiz — which strategy?

Q1. Given an unsorted array, find all pairs that sum to a target value. What is the optimal approach?

  • Sort the array and use nested loops to find each pair in O(n²)
  • Scan once storing each value in a HashSet; check if complement exists — O(n)
  • Sort the array and use two pointers converging from both ends — O(n log n)
  • Use dynamic programming with a 2D table tracking partial sums — O(n²)
HashSet complement lookup: for each element x, check if (target - x) is already in the set. O(n) time, O(n) space. Note: Two Pointers also works (O(n log n) due to sort) but requires sorting. If the array is already sorted, two pointers is optimal O(n). If unsorted, HashMap wins.

Q2. "Find the longest substring with at most K distinct characters." Which strategy?

  • Sliding window with a frequency map; shrink left when distinct count exceeds K
  • Sort the string and use binary search to find the longest run
  • Dynamic programming with dp[i][j] = longest ending at i with j distinct chars
  • Backtracking: generate all substrings and filter by distinct count
Classic variable sliding window. Maintain a frequency map of chars in the window. Expand right always. When map.size() > K, shrink from left (decrement freq, remove if 0). Update max window size at each right. O(n) time — each character is added once and removed at most once.

Q3. You have a linked list and need to find the middle node in one pass. Which technique?

  • Store all nodes in an ArrayList, return the middle index — O(n) space
  • Count nodes first, then traverse again to the middle — two passes
  • Fast/slow pointers: fast moves 2 steps, slow 1; when fast reaches end, slow is at middle
  • Use recursion: unwind the call stack to count from the tail — O(n) stack
Fast/slow (Floyd's) pattern. Fast pointer moves 2 nodes per step, slow moves 1. When fast.next == null (odd length) or fast.next.next == null (even length), slow is at the middle. O(n) time, O(1) space — no extra storage, single pass.

Q4. You need to find the shortest path in a graph where all edges have equal weight. Which algorithm?

  • DFS with a visited set — explores deep before wide, misses shortest path
  • BFS with a queue — each level = one step; first time a node is visited = shortest path
  • Dijkstra with a priority queue — correct but overkill for uniform edge weights
  • Dynamic programming with dp[node] = min cost — requires topological order
BFS guarantees shortest path in an unweighted (or equal-weight) graph because it explores all nodes at distance d before distance d+1. The first time BFS visits a node, it has taken the fewest hops. Dijkstra also works but has O((V+E) log V) overhead from the priority queue — wasteful when all weights are equal. BFS is O(V+E).

Q5. "Given n tasks with deadlines and profits, find maximum profit if you can do one task per time slot." Which strategy?

  • DP with dp[t] = max profit achievable in t time slots — O(n·T)
  • BFS exploring all task orderings — exponential branches
  • Backtracking: try all assignments and keep the best — O(n!)
  • Greedy: sort by profit descending; for each task, assign to latest available slot before deadline
Greedy job scheduling: sort tasks by profit descending (take the most valuable first). For each task, try to schedule it in the latest available slot ≤ deadline (use Union-Find or a boolean slot array). This greedy works because higher-profit tasks should "claim" the latest possible slot, leaving earlier slots for lower-profit tasks. O(n log n) sort + O(n·d) slot scan.

Q6. You're generating all valid combinations of N pairs of brackets. Which strategy?

  • Dynamic programming: build dp[i] from dp[i-1] by prepending/appending brackets
  • BFS: start from empty string, branch into two states at each step
  • Backtracking: add '(' if open count < n; add ')' if close count < open count; base case: length = 2n
  • Sliding window over a prebuilt string of brackets to extract valid substrings
Backtracking with pruning. State = (current string, open count, close count). Two choices at each step: add '(' if open < n; add ')' if close < open. Backtrack when neither is valid. This avoids generating invalid strings early — much more efficient than brute force. The constraint "close < open" is the pruning condition that makes backtracking efficient here.
