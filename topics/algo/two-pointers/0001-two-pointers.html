Lesson 01 — Two Pointers

Category: Algo · Difficulty: Medium-Hard · Est. time: 15 min · Lesson 1 of N

Two Pointers is the pattern behind Team Formation (q018), 3Sum, Container With Most Water, and dozens of other interview problems. The idea is simple: instead of a nested loop (O(N²)), maintain two indices that converge — O(N) per pass, O(N log N) total after sorting.

What you will be able to do after this lesson Recognise a Two Pointers problem, set up the sorted + converging pointer skeleton in under 2 minutes, and handle the duplicate-skipping step that separates medium from hard solutions.

2. Opposite ends — step-by-step (Team Formation)

You saw this in q018. Sort → fix target sum → L and R converge.

Input: skill = [3, 2, 1, 2] Sorted: [1, 2, 2, 3] L=0, R=3 target = 1+3 = 4 Step 1: nums[L]+nums[R] = 1+3 = 4 == target ✓ efficiency += 1*3 = 3 L++, R-- [1, 2, 2, 3] L=1, R=2 Step 2: nums[L]+nums[R] = 2+2 = 4 == target ✓ efficiency += 2*2 = 4 L++, R-- → L > R, done Result: 3 + 4 = 7

3. Three pointers — 3Sum step-by-step

Find all unique triplets in an unsorted array that sum to 0. Key insight: fix one element with outer loop, use Two Pointers for the remaining two.

Input: [-1, 0, 1, 2, -1, -4] Sorted: [-4, -1, -1, 0, 1, 2] 0 1 2 3 4 5 ─── i=0, nums[i]=-4 ─────────────────────────────── [-4, -1, -1, 0, 1, 2] L=1, R=5 sum = -4 + -1 + 2 = -3 < 0 → L++ [-4, -1, -1, 0, 1, 2] L=2, R=5 sum = -4 + -1 + 2 = -3 < 0 → L++ [-4, -1, -1, 0, 1, 2] L=3, R=5 sum = -4 + 0 + 2 = -2 < 0 → L++ [-4, -1, -1, 0, 1, 2] L=4, R=5 sum = -4 + 1 + 2 = -1 < 0 → L++ → L==R, stop ─── i=1, nums[i]=-1 ─────────────────────────────── [-4, -1, -1, 0, 1, 2] L=2, R=5 sum = -1 + -1 + 2 = 0 ✓ → add [-1,-1,2] L++, R-- skip duplicates on both sides [-4, -1, -1, 0, 1, 2] L=3, R=4 sum = -1 + 0 + 1 = 0 ✓ → add [-1,0,1] L++, R-- → L==R, stop ─── i=2, nums[i]=-1 == nums[1] → SKIP (duplicate) ─── ─── i=3, nums[i]=0 ──────────────────────────────── [-4, -1, -1, 0, 1, 2] L=4, R=5 sum = 0 + 1 + 2 = 3 > 0 → R-- → L==R, stop Result: [[-1,-1,2], [-1,0,1]]

4. The duplicate-skipping rule — why it matters

3Sum asks for unique triplets. Without deduplication, [-1,0,1] appears twice (once for each -1). Three skip rules, all required: 

Arrays.sort(nums);
List<List<Integer>> result = new ArrayList<>();

for (int i = 0; i < nums.length - 2; i++) {

    // Skip 1: outer loop — same value as previous i
    if (i > 0 && nums[i] == nums[i - 1]) continue;

    // Early termination: smallest possible sum already > 0
    if (nums[i] > 0) break;

    int l = i + 1, r = nums.length - 1;
    while (l < r) {
        int sum = nums[i] + nums[l] + nums[r];
        if (sum == 0) {
            result.add(List.of(nums[i], nums[l], nums[r]));
            // Skip 2: left pointer — move past duplicates
            while (l < r && nums[l] == nums[l + 1]) l++;
            // Skip 3: right pointer — move past duplicates
            while (l < r && nums[r] == nums[r - 1]) r--;
            l++; r--;
        } else if (sum < 0) {
            l++;   // sum too small — move left pointer right
        } else {
            r--;   // sum too large — move right pointer left
        }
    }
}
Complexity Time: O(N log N) sort + O(N²) nested scan = O(N²). Space: O(1) ignoring output list — no auxiliary data structure. Brute force 3-loop = O(N³). Two Pointers reduces one loop to O(N) convergence.

5. When is Two Pointers the right pattern?

  • Problem involves pairs or triplets from one array
  • Constraint says array is sorted, or sorting is free (no ordering requirement on output)
  • Brute force is O(N²) or O(N³) — Two Pointers cuts one dimension
  • Problem asks for sum == target, closest sum, count of valid pairs
Two Pointers does NOT work when Order matters (you cannot sort), elements cannot be reused but you need to track which were used (use a HashMap instead), or target changes dynamically (use Sliding Window).

6. Retrieval quiz

Q1. What is the time complexity of 3Sum using sort + Two Pointers?

  • A) O(N log N) — sorting dominates
  • B) O(N²) — one outer loop × one inner convergence pass each
  • C) O(N³) — three nested loops
  • D) O(N log² N) — sorting repeated per outer iteration
Sort is O(N log N). The outer loop runs N times; the inner Two Pointers pass is O(N) per iteration (L and R together traverse at most N elements). Total: O(N log N + N²) = O(N²). The O(N log N) sort is dominated by the O(N²) scan.

Q2. Why must the array be sorted before applying opposite-ends Two Pointers?

  • A) Sorting removes duplicates, which simplifies the skip logic
  • B) Java's Arrays.sort is required by the problem constraints
  • C) Sorted order gives a deterministic move rule: sum too small → move L right; sum too large → move R left. Without sorting, moving either pointer could increase or decrease the sum unpredictably.
  • D) Sorting ensures that all valid pairs appear at adjacent indices
The entire correctness of Two Pointers rests on the monotonic property of sorted order. If sum < target, the only way to increase it is to move L rightward (larger value). If sum > target, move R leftward. Without sorting, these moves have no guaranteed direction — you'd need to check all combinations: O(N²).

Q3. In 3Sum, how do you skip duplicate triplets caused by the outer loop index i?

  • A) if (i > 0 && nums[i] == nums[i-1]) continue; — skip if same value as previous outer element
  • B) if (nums[i] == nums[i+1]) continue; — skip if next element is the same
  • C) Use a HashSet to store seen values of nums[i] and skip if already seen
  • D) Sort descending so duplicates are never adjacent
Check nums[i] == nums[i-1] (not i+1). Checking the previous ensures you only process the FIRST occurrence of each value. Checking the next would skip the first occurrence and process the second — wrong. The guard i > 0 prevents out-of-bounds on the first iteration.

Q4. After finding a valid triplet in 3Sum, you add it to the result. What must happen next before continuing the inner while loop?

  • A) Break out of the inner loop — only one triplet possible per i
  • B) Move only L right by one: l++
  • C) Move only R left by one: r--
  • D) Move both L and R inward, then skip duplicates on both sides before the next iteration
A valid triplet is found. There may be more valid triplets for the same i (e.g. [-2,0,2] and [-2,1,1] both sum to 0). So both pointers must move inward. Then skip duplicates: while nums[l]==nums[l+1] l++; while nums[r]==nums[r-1] r--; then l++; r--. Skipping only one side leaves duplicate triplets in the result.
